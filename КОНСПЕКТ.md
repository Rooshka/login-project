# Конспект проекта NORTHSTAR

Это учебный сайт с регистрацией, входом, выходом и личным кабинетом. Структура похожа на структуру проекта учителя: маршруты вызывают контроллеры, контроллеры обращаются к моделям, а модели работают с MySQL через PDO.

## 1. Как устроен MVC

- **Model** — `src/model/UserModel.php`. Отправляет SQL-запросы в MySQL и получает пользователей.
- **View** — папка `views`. Отвечает за HTML-страницы.
- **Controller** — папка `src/controller`. Получает запрос, проверяет данные и выбирает представление.

Общий путь при регистрации:

1. Пользователь открывает `/register`.
2. `Routes.php` вызывает `AuthController::registerForm()`.
3. `Controller.php` подключает `header.php` и `register.php`.
4. Пользователь отправляет форму методом POST.
5. `Routes.php` проверяет CSRF-токен и вызывает `AuthController::register()`.
6. `AuthController` проверяет данные в PHP.
7. `UserModel` добавляет пользователя в MySQL.
8. `password_hash()` превращает пароль в хеш.
9. Сессия запоминает вошедшего пользователя, после чего открывается `/account`.

## 2. Файлы в корне

### `index.php`

Главная точка входа. Запускает сессию, подключает основные классы, создаёт объект `Routes` и регистрирует адреса сайта. Блок `PHP_SAPI === 'cli-server'` нужен встроенному PHP-серверу, чтобы CSS и JavaScript отдавались как обычные файлы.

### `.htaccess`

Правило для Apache: если адрес не соответствует существующему файлу или папке, запрос передаётся в `index.php`. При запуске через `php -S localhost:8000 index.php` этот файл обычно не участвует.

### `README.md`

Инструкция по установке и запуску.

### `КОНСПЕКТ.md`

Учебное объяснение устройства проекта.

## 3. `src/core`

### `config.php`

Функция `config()` возвращает массив настроек подключения: адрес MySQL, порт, имя базы, пользователя, пароль и кодировку. Настройки собраны в одном месте.

### `Database.php`

Класс `Database` создаёт соединение PDO. `static` позволяет вызвать `Database::connect()` без создания объекта. `new PDO()` устанавливает соединение с MySQL. `PDO::ATTR_ERRMODE` включает исключения при ошибках, `PDO::FETCH_ASSOC` возвращает строки как ассоциативные массивы.

### `Routes.php`

Хранит адреса в массиве `$routes`. Методы `get()` и `post()` регистрируют обработчики. Метод `run()` получает HTTP-метод и путь из `$_SERVER`, проверяет POST-запросы через CSRF и вызывает нужный метод контроллера. `checkAccess()` проверяет, вошёл ли пользователь и есть ли у него нужная роль.

### `Auth.php`

Проверяет состояние входа по `$_SESSION['user']`. `user()` возвращает данные текущего пользователя. `hasRole()` проверяет роль пользователя.

### `Csrf.php`

Создаёт случайный токен для формы и проверяет его при отправке POST. Это защита от поддельных запросов с другого сайта. `hash_equals()` безопасно сравнивает токены.

### `helpers.php`

Вспомогательные функции для HTML-форм. `e()` безопасно выводит текст через `htmlspecialchars()`. `csrf_field()` добавляет скрытое поле с CSRF-токеном. `inputClass()`, `ariaError()` и `fieldError()` помогают показать ошибки рядом с полями.

## 4. `src/model`

### `UserModel.php`

Класс для работы с таблицей `users`.

- `__construct()` создаёт подключение PDO.
- `findByEmail()` ищет пользователя по email.
- `create()` добавляет имя, email и хеш пароля.

В запросах используются `prepare()` и `execute()`. Знак `?` — место, куда PDO безопасно подставляет значение параметра.

## 5. `src/controller`

### `Controller.php`

Общий родительский контроллер. Метод `view()` подключает общий header, нужную страницу и footer. `extract($data)` превращает элементы массива `$data` в переменные для шаблона.

### `HomeController.php`

Открывает главную страницу `views/home.php`.

### `AuthController.php`

Главная логика регистрации, входа и выхода.

- `registerForm()` показывает форму регистрации.
- `register()` принимает `$_POST`, проверяет поля, проверяет уникальность email, создаёт хеш пароля и сохраняет пользователя.
- `loginForm()` показывает форму входа.
- `login()` ищет email и сравнивает введённый пароль с хешем через `password_verify()`.
- `logout()` очищает сессию.

`session_regenerate_id(true)` обновляет ID сессии после входа или регистрации, чтобы усложнить фиксацию сессии.

### `AccountController.php`

Показывает личный кабинет. Доступ к `/account` ограничен маршрутизатором: пользователь должен иметь роль `user`.

## 6. `views`

### `home.php`

Главная страница с описанием функций проекта и ссылками на вход и регистрацию.

### `register.php`

Форма регистрации. У каждого поля есть `name`, по которому PHP получает значение из `$_POST`. Ошибки PHP выводятся под полями. Атрибут `data-validate="register"` включает проверку JavaScript.

### `login.php`

Форма входа по email и паролю. Атрибут `data-validate="login"` включает клиентскую проверку.

### `account.php`

Закрытая страница с именем, email и ID вошедшего пользователя.

### `templates/header.php`

Верхняя часть HTML-документа, подключение CSS и JavaScript, меню. Если пользователь вошёл, показывается ссылка на кабинет и POST-форма выхода.

### `templates/footer.php`

Закрывает основную часть HTML и выводит нижнюю строку сайта.

## 7. `public/js/validation.js`

JavaScript запускается после загрузки страницы. Он находит формы с `data-validate`, проверяет имя, email, пароль и подтверждение пароля. `addEventListener()` добавляет обработчики событий `submit` и `input`. `preventDefault()` отменяет отправку формы, если найдены ошибки. Сообщения появляются рядом с полями.

JavaScript не заменяет PHP-проверку: пользователь может отключить JavaScript или отправить запрос вручную. Поэтому те же важные условия проверяются в `AuthController.php`.

## 8. `public/css`

### `global.css`

Общие правила: сброс отступов, шрифты, ширина контейнера и базовая раскладка.

### `main.css`

Цвета, шапка, кнопки, формы, ошибки, главная страница, личный кабинет и адаптация под небольшие экраны. Класс `.field` оформляет группу поля, `.input` — само поле, `.field__error` — текст ошибки.

## 9. `database/login_project.sql`

SQL-файл создаёт базу `login_project` и таблицу `users`.

- `id` — уникальный номер пользователя.
- `name` — имя.
- `email` — адрес почты, уникальный благодаря `UNIQUE`.
- `password_hash` — хеш пароля, а не исходный пароль.
- `role` — роль пользователя, по умолчанию `user`.
- `created_at` — дата создания аккаунта.

## 10. Важные понятия

- `$_POST` — массив данных, отправленных формой методом POST.
- `$_SERVER` — встроенный массив информации о запросе и сервере.
- `$_SESSION` — данные пользователя между запросами.
- `isset()` — проверяет, установлена ли переменная или элемент массива.
- `if / elseif / else` — условия.
- `class` — описание класса.
- `new` — создание объекта.
- `public` — доступный снаружи метод или свойство.
- `private` — доступный только внутри класса.
- `protected` — доступный внутри класса и его наследников.
- `extends` — наследование класса.
- `return` — возврат значения из функции или метода.
- `require_once` — подключает файл один раз.
- `prepare()` и `execute()` — подготовка и выполнение SQL-запроса.
- `password_hash()` — создание хеша пароля.
- `password_verify()` — проверка пароля по хешу.
- `header('Location: ...')` — перенаправление браузера.

## 11. Почему есть две проверки

JavaScript проверяет поля до отправки, чтобы пользователь сразу увидел ошибку. Но JavaScript выполняется в браузере и может быть отключён. PHP работает на сервере, поэтому именно PHP-проверка решает, можно ли сохранить пользователя или выполнить вход. Нельзя полагаться только на JavaScript.
